# Next session: a Content Security Policy for batesstamp.com

## Context

batesstamp.com is a static site of 8 free legal tools plus Email to PDF, deployed by Cloudflare
Pages when `main` is pushed (live in about 20 s). Its promise is that documents never leave the
browser. There is no CSP today. A `connect-src 'self'` policy, plus tight `script-src`, would
back that promise with something the browser enforces rather than something we only say. The
owner chose CSP as this session's focus on 2026-10-08. The site is otherwise in a clean state:
`main` is at `13989ed` plus the closeout commit, deployed, and the suite is green at 232/232.

## First action

Take an inventory before designing anything. Run:

```bash
cd /home/ctibs/Projects/legal-tools
git log --oneline -3 && git status --short
grep -rho 'src="https://[^/"]*' batesstamp --include='*.html' | sort | uniq -c   # external scripts
grep -rhoE 'href="https://[^/"]*' batesstamp --include='*.html' | sort | uniq -c # external styles/preconnects
grep -rc '<script>' batesstamp --include='*.html' | grep -v ':0'                    # inline scripts per page
grep -rlE ' on[a-z]+="' batesstamp --include='*.html'                               # inline handlers (was 0)
grep -rn 'workerSrc\|new Worker\|blob:\|data:' batesstamp shared --include='*.js' --include='*.html' | head -40
```

Inventory as of 2026-10-08:
- External script hosts: cdnjs (5 tags), unpkg (11), and the self-hosted analytics at
  `umami.ctibs.app` (13).
- Cloudflare injects its own beacon, `static.cloudflareinsights.com`.
- Fonts are self-hosted (`fonts.css`).
- There are inline `<script>` blocks, including the pdf.js `workerSrc` one-liners, and
  `email-to-pdf` has 12 `<script` tags. No inline `on*=` handlers.

## Pending work

1. **Design the policy and get the owner's sign-off before shipping.** Decisions for the owner:
   - **Inline scripts.** Either move them to files, so `script-src` can drop `'unsafe-inline'`,
     or use hashes.
   - **Where the header lives.** `batesstamp/_headers` (Cloudflare Pages; none exists yet),
     a `<meta>` tag, or both.
   - **Report-only first?** Cloudflare Pages can serve `Content-Security-Policy-Report-Only`.
     There is no report endpoint unless we add one (Umami can't take one).
   - **The Cloudflare beacon.** Allow it, or turn Web Analytics off, since Umami already
     covers analytics.

   Likely needs:
   - `script-src 'self' cdnjs unpkg umami.ctibs.app` (plus the beacon if kept);
   - `worker-src 'self'` (pdf.js worker is now vendored);
   - `connect-src 'self' umami.ctibs.app`;
   - `img-src 'self' data: blob:` (the email preview uses blob URLs for inline images, and
     data: images);
   - `style-src` (check for inline `style=` attributes and `<style>` blocks);
   - `frame-ancestors 'none'`, `base-uri 'none'`, `form-action 'none'`, `object-src 'none'`.

   Check `shared/eml/blocks-to-html.js` (preview `<img>` from blob/data), pdf-lib, fontkit
   (does it `eval` or `new Function`?), JSZip and Sortable for things CSP would block.
2. **Test every tool page under the policy in Chromium, with the console and network watched.**
   Load each page, process a real file, download the result, and check that the console shows no
   CSP violations. For Email to PDF: preview, convert, combined batch, ZIP. Run
   `/tmp/run-tests` (the test page is dev-only, but make sure the policy doesn't break the
   dev build).
3. **Run the `auditing-network-exposure` skill's pre-public checklist** if `_headers` changes
   anything that faces the internet. A CSP mostly tightens things, but the CLAUDE.md rule
   applies to header changes.
4. **Push, then smoke-test live**:
   - `curl -sI` shows the header;
   - every tool works end to end in headless Chromium;
   - no CSP violations in the console. Ignore the beacon's `ERR_CERT_AUTHORITY_INVALID`; that
     is the headless shell's trust store.
5. **Cheap leftovers, if time allows:**
   - remove the unused pdf.js from filing-assembler (it loads pdf.js and never calls it; confirm
     with a grep for `pdfjsLib` first);
   - the "such as" list in the certificate's removed-elements sentence
     (`shared/eml/certificate.js`) omits link, base, svg and input.

## Watch out for

- **Pushing `main` deploys.** Get each batch reviewed by an independent Opus reviewer before
  pushing. On 2026-10-08, two review rounds found real hangs in Claude's own fixes.
- **A CSP that is wrong fails silently for users.** The page just stops working. Test every
  tool, not a sample.
- **Missing paths on the live site return the homepage with HTTP 200**, so check the body.
- **`networkidle` never fires on the live page.** Use a fixed wait.
- **Playwright MCP is broken here.** Drive Chromium directly with
  `require('/home/ctibs/.npm/_npx/86170c4cd1c5da32/node_modules/playwright')` and
  `executablePath` set to
  `~/.cache/ms-playwright/chromium_headless_shell-1243/chrome-headless-shell-linux64/chrome-headless-shell`.
- **Module scripts delay DOMContentLoaded until their imports load.** To test "before init",
  use `waitUntil: 'commit'`.
- **Never `pkill -f`.** Kill servers by PID via `lsof -ti :<port>`.
- **Root `shared/` is source; `batesstamp/shared/` is build output.** `batesstamp/vendor/` is
  committed source, apart from the dev-only `pdf*.min.js` at its top level.
- **Run the suite with**
  `cp docs/closeouts/2026-09-14-0841-run-tests.sh /tmp/run-tests && PORT=8792 /tmp/run-tests`.
  Run `python3 docs/fixtures/eml/generate.py` first, because fixture 07 is gitignored. Leave
  the tree in a plain-build state (`bash build.sh`).
