# Next Session — Pleading Line Number Overlay Tool

## Context

BatesStamp currently has a **Pleading Paper** tool that generates *blank*
numbered-line paper (`batesstamp/pleading-paper/index.html`). A prior session
(2026-08-07) designed a companion tool that overlays those numbered lines onto
a PDF the user already has — a brief drafted in Word without a pleading
template, or a filing received without numbers.

The design was fully worked out and approved by the user, but **the session
ended before the spec was written and before any code was produced**. This
prompt carries the complete design so it can be resumed without re-deriving
it. Repo was clean at `34b37cc`.

### 2. Geometry — the core, get this right first

One pure function is the whole tool:

```
computeOverlay(pageWidthPt, pageHeightPt, settings)
  → { numbers: [{n, x, y}], rules: [{x, yTop, yBottom}] }
```

Returns page-space points only — no drawing, no DOM. **Both the live preview
and the PDF export must consume this same function.** If they compute
positions separately they will drift, and a lying preview is worse than no
preview in a tool whose entire job is visual alignment.

For line *n* (1-indexed):

```
baselineY = pageHeight − (firstLineTop × 72) − ((n − 1) × lineSpacing)
```

Two deliberate departures from the existing blank generator — both are
load-bearing:

- **`lineSpacing` is an explicit user input (default 24pt), not
  `usableHeight / lineCount`.** It must match the source document's leading.
- **`(n − 1)`, not `n`,** so line 1 lands exactly at the user's "first line
  from top" value and the control means what its label says.

Other rules:

- Numbers right-aligned against the gutter: `x = ruleX − numWidth − 8`,
  clamped to ≥ 4, so 1- and 2-digit numbers share a right edge.
- Use each page's own `page.getSize()` — never hardcode 612×792 — so a
  document mixing Letter and Legal still places correctly.
- Rule vertical extent derives from the **line block** (top of line 1 to just
  below the last baseline), not from margins. In overlay mode we don't control
  the document's margins.

Format presets, lifted from `pleading-paper/index.html:417` but **dropping the
`margins` field** (unused here):

- California — 28 lines, rules at `[1.0, 1.25]` inches
- Federal — 25 lines, rule at `[1.0]`
- Custom — user-editable

**Rotation:** read `page.getRotation().angle`. `drawText` works in unrotated
page space, so rotated pages would get numbers on the wrong edge. Detect,
**skip those pages, and name them in the status output** ("pages 7, 8 are
rotated and were skipped"). The page-range field covers rotated landscape
exhibits.

### 3. UI

Numbered sections, matching the other tools' layout:

1. **Upload** — `initFileDropZone` from `shared/file-handler.js`, single file.
2. **Format** — California / Federal / Custom radio group, same markup as the
   generator.
3. **Alignment** — first line from top (in, default 1.0), line spacing (pt,
   default 24), lines per page, number size (pt, default 10), vertical rules
   toggle (default on) with editable positions under Custom.
4. **Pages** — range field. Lift `parsePageRange` from
   `page-extractor/index.html:365`.

### 4. Live preview

Canvas + SVG, following the pattern at `redaction/index.html:351-366`.

- pdf.js canvas re-renders **only on page change**.
- The number/rule overlay is an SVG layer recomputed on every input change —
  interactive speed, no PDF regeneration.
- SVG `<text>` y *is* the baseline, so `computeOverlay` output maps across with
  a single flip: `svgY = pageHeight − pdfY`. No second geometry implementation.
- Keep **only the current page's canvas** in memory. 300-page PDFs are
  realistic here.

### 5. Collision scan

On load and on debounced settings change, walk in-range pages'
`getTextContent()`, take `min(item.transform[4])` per page, and flag pages
where that falls left of the rightmost rule. Cache text content per page after
first read. Report as a warning listing page numbers. **Never block export** —
a small overlap on one page may be perfectly acceptable to the filer.

State plainly in the UI that this **checks the text layer only**. Scanned
pages, vector graphics, and images are invisible to it; the preview is the
fallback there. A banner that quietly reads "clean" on a scanned document
would be actively misleading.

### 6. Export

`PDFDocument.load(buf, { updateMetadata: false })` — matching
`bates-stamp/index.html:534`, preserving the original metadata rather than
stamping ours over it (the site has a metadata-stripper for users who want it
gone). Embed `StandardFonts.TimesRoman`, draw per `computeOverlay`, save, hand
to `window.downloadPdf`.

Each failure mode gets a specific message, not a generic catch:
password-protected PDF (pdf-lib throws on load), corrupt file, empty page
range, and every in-range page rotated so nothing would be drawn.

### 7. Verification

There is **no test framework in this repo** (static site, no `package.json`)
and one should not be introduced for a single tool. Plan:

- A small node self-check of `computeOverlay` against known values. This is
  where a math error is invisible and expensive.
- Playwright MCP against the built page with fixture PDFs: 12pt
  double-spaced, mixed Letter/Legal, a rotated page, a scanned/no-text-layer
  page, and an encrypted file.

Report what actually passes. Do not assert it works without running it.

## Watch Out For

- **Do not reuse `bates-stamp`'s `scaleContent`/`translateContent` whitespace
  border to make room for the gutter.** It exists and is tempting. Shrinking
  page content can silently push a conforming brief out of compliance with
  court font-size and margin rules (CRC 2.104/2.107, most federal local
  rules). Overlay only; warn on collisions rather than mangling the document.
- **The blank generator's spacing math does not transfer.** Copying
  `usableHeight / lineCount` into this tool will produce numbers that look
  plausible and are wrong. See Geometry above.
- Two similarly-named tools now sit in the nav ("Pleading Paper" vs "Pleading
  Line Numbers"). Their descriptions in `shared/tools.js` need to make the
  difference obvious at a glance — generate blank vs add to an existing PDF.
- Per user preference: **no emoji icons in the UI — SVG only**, and tool cards
  must be fully clickable links.
